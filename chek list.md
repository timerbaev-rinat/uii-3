1. Объекты учёта (что именно учитываем)
Отметьте типы объектов и для каждого зафиксируйте обязательные атрибуты:
•	Оборудование (компьютеры, проекторы, интерактивные доски, принтеры): 
o	инвентарный номер, модель/марка, серийный номер, год приобретения, состояние, гарантийный срок, кабинет/место хранения.
•	Мебель (парты, стулья, шкафы, стеллажи): 
o	инвентарный номер, тип, количество, материал, состояние, кабинет/место хранения.
•	Спортивный инвентарь и оборудование (мячи, тренажёры, маты): 
o	инвентарный/учётный номер, тип, комплектность, состояние, место хранения, срок службы.
•	Учебно лабораторное оборудование (микроскопы, химреактивы в таре, наборы): 
o	инвентарный номер, состав комплекта, нормы расходования/учёта (если применимо), условия и место хранения.
•	Иные объекты (по необходимости: музыкальные инструменты, костюмы, техника для столовой и т.п.): 
o	перечень типов, специфика учёта (комплектность, расходники, периодическая поверка).
Дополнительно:
•	Требуется привязка к помещениям/кабинетам, по подразделениям.
•	Фотофиксации при постановке на учёт и при инвентаризации, при необходимости.

6. Автоматическая идентификация (QR/DataMatrix/штрихкоды)
Внедрение технологий автоматической идентификации для ускорения учёта и инвентаризации:
•	Генерация меток:
o	форматы: QR-код, DataMatrix (ГОСТ Р 58201-2018), штрихкод Code128/EAN13;
o	содержание метки: инвентарный номер, ссылка на веб-карточку (URL), контрольная сумма;
o	правила именования файлов этикеток, шаблоны печати (A4, термопринтеры 50x30мм).
•	Печать этикеток:
o	поддержка принтеров этикеток (Godex, Zebra, Xprinter);
o	пакетная печать по списку объектов, предпросмотр перед печатью;
o	учёт расхода этикеток (журнал печати).
•	Сканирование и распознавание:
o	сканирование через камеру мобильного устройства (PWA/приложение);
o	поддержка USB/Bluetooth сканеров штрихкодов;
o	режим «массового сканирования» при инвентаризации (до 100 объектов за сессию);
o	обработка ошибок чтения (повтор, ручной ввод).
•	Проверка подлинности:
o	контроль дублирования меток (запрет на повторное использование номера);
o	маркировка защищённых объектов (пломбы, голограммы — опционально).
Дополнительно:
•	Требования к устойчивости этикеток: влагозащита, температурный режим (-20°C...+50°C), срок службы ≥5 лет.
•	Резервный механизм: возможность работы без сканера (ручной ввод инвентарного номера).

7. Уведомления и события
Система оповещений для своевременного реагирования на критические события:
•	Типы уведомлений:
o	окончание гарантийного срока (за 30/14/7 дней);
o	наступление срока плановой инвентаризации (за 14 дней);
o	критический износ объекта (>80%);
o	просрочка поверки оборудования (для лабораторного оборудования);
o	утверждение/отклонение операций (списание, перемещение);
o	расхождения при инвентаризации (недостача/излишек).
•	Каналы доставки:
o	e-mail (SMTP, шаблоны писем с логотипом учреждения);
o	push-уведомления в PWA/мобильном приложении;
o	внутрисистемные уведомления (колокольчик в интерфейсе);
o	SMS (опционально, через шлюз провайдера).
•	Настройки уведомлений:
o	индивидуальные подписки по ролям (кто какие события получает);
o	расписание рассылки (ежедневно/еженедельно/немедленно);
o	шаблоны текстов уведомлений (редактируемые администратором).
•	Журнал уведомлений:
o	история отправленных уведомлений (дата, канал, статус доставки);
o	отчёт о прочтении (для push/e-mail с трекингом).
Дополнительно:
•	Эскалация: если ответственное лицо не отреагировало за 3 дня — уведомление руководителю.
•	Групповые уведомления: массовая рассылка по подразделениям (например, о начале инвентаризации).

8. Валидация данных и производительность
Требования к качеству данных и быстродействию системы:
•	Правила валидации при вводе:
o	обязательные поля (инвентарный номер, тип, место хранения);
o	уникальность инвентарного номера в пределах учреждения;
o	форматы дат (ДД.ММ.ГГГГ), числовых полей (только положительные значения);
o	справочники: ограниченные списки (типы объектов, кабинеты, материалы);
o	контроль логических противоречий (дата списания ≥ даты приобретения, гарантия ≤ срока службы).
•	Контроль качества данных:
o	автоматическая проверка дублей (по серийному номеру, модели);
o	валидация при импорте из CSV/XML (отчёт об ошибках импорта);
o	регулярный аудит целостности (раз в квартал, отчёт о проблемах).
•	Требования к производительности:
o	время отклика интерфейса: ≤2 сек для обычных операций, ≤5 сек для сложных отчётов;
o	поддержка одновременной работы: ≥50 пользователей;
o	обработка массовых операций: импорт до 1000 записей за ≤1 мин;
o	время формирования отчётов: до 10000 строк — ≤10 сек.
•	Нагрузочное тестирование:
o	пиковая нагрузка: 100 пользователей одновременно;
o	стресс-тест: непрерывная работа 24 часа под нагрузкой 80% от пика;
o	деградация: при превышении нагрузки — очередь задач с уведомлением.
Дополнительно:
•	Мониторинг производительности: дашборд с метриками (время отклика, количество ошибок, загрузка CPU/памяти).
•	Оптимизация: индексация БД, кэширование справочников, пагинация больших списков.

9. Роли и права доступа (дополнение)
Расширение матрицы ролей для полного цикла работ:
•	Педагог / сотрудник учреждения:
o	подача заявок на ремонт/перемещение оборудования;
o	просмотр имущества в закреплённом кабинете;
o	подтверждение приёмки оборудования после ремонта;
o	ограничение: нет доступа к финансовым данным, списанию.
•	Бухгалтер (новая роль):
o	просмотр данных об остаточной стоимости, износе;
o	выгрузка отчётов для бухгалтерского учёта (формат 1С);
o	участие в комиссии по списанию (электронная подпись актов);
o	ограничение: нет доступа к редактированию карточек имущества.
•	Технический специалист / ремонтник:
o	фиксация выполненных работ (акты, фото до/после);
o	обновление статуса ремонта (в работе/готово/возврат);
o	добавление комментариев к карточке оборудования;
o	ограничение: только объекты со статусом «В ремонте».
Дополнительно:
•	Матрица полномочий (CRUD): таблица «роль — объект — действие» (Create, Read, Update, Delete).
•	Временные роли: назначение на период отпуска/болезни основного ответственного.

10. Отчёты и выгрузки (дополнение)
Расширение перечня отчётных форм для полного контроля:
•	Карточка объекта учёта:
o	полная информация об объекте (все атрибуты + история + фото);
o	формат: A4, PDF, с QR-кодом для печати;
o	использование: при инвентаризации, проверках, передаче дел.
•	Реестр гарантийных обязательств:
o	список объектов с действующей гарантией (поставщик, срок, контакты);
o	фильтрация: истекающие в текущем месяце/квартале;
o	формат: Excel с условным форматированием (красный — истекает <30 дней).
•	Отчёт по местам хранения (кабинетам):
o	имущество по каждому кабинету с фотофиксацией;
o	ответственное лицо, дата последней проверки;
o	формат: PDF с оглавлением по кабинетам.
•	Сводный отчёт для муниципалитета:
o	агрегированные данные по учреждению (категории, стоимость, износ);
o	сравнение с предыдущими периодами (динамика);
o	формат: XML/JSON по утвержденному шаблону ОМС.
•	Журнал операций:
o	хронология всех действий пользователей за период;
o	фильтрация по типу операции, пользователю, объекту;
o	формат: Excel/PDF с возможностью выгрузки аудита.
Дополнительно:
•	Конструктор отчётов: возможность создания пользовательских отчётов (выбор полей, фильтров, группировок).
•	Планировщик отчётов: автоматическая генерация и отправка по расписанию (еженедельно/ежемесячно).

11. Документооборот и согласование
Электронный документооборот для операций с имуществом:
•	Шаблоны документов:
o	акт приёма-передачи, акт списания (ОС-4), инвентаризационная опись (ИНВ-3);
o	требование-накладная (М-11), акт о неисправности;
o	редактируемые шаблоны (Word/PDF-формы с автозаполнением).
•	Маршруты согласования:
o	одноуровневое (ответственный → директор);
o	многоуровневое (ответственный → завхоз → бухгалтер → директор);
o	параллельное (несколько согласующих одновременно);
o	настройка маршрутов по типу операции и сумме (для ценного имущества).
•	Электронная подпись (ЭП):
o	поддержка квалифицированной ЭП (КЭП) для утверждения актов;
o	простая электронная подпись (ПЭП) для внутренних документов;
o	интеграция с ЕСИА/Госуслуги (опционально).
•	Версионность документов:
o	хранение всех версий документа с историей изменений;
o	сравнение версий (diff-режим);
o	блокировка редактирования после утверждения.
Дополнительно:
•	Печать документов: возможность печати на бланках учреждения с реквизитами.
•	Архив документов: хранение сканов бумажных оригиналов (PDF, срок ≥5 лет).

12. Тестирование и приёмка системы
Критерии готовности системы к промышленной эксплуатации:
•	Функциональное тестирование:
o	покрытие тестами: ≥95% бизнес-процессов из разделов 1-2;
o	тест-кейсы: позитивные/негативные сценарии, граничные значения;
o	регрессионное тестирование после каждого обновления.
•	Интеграционное тестирование:
o	проверка обмена данными с внешними системами (1С, ГИС МУ, Казначейство);
o	тестирование API (REST/SOAP), валидация форматов JSON/XML;
o	нагрузочное тестирование интеграционных точек.
•	Приёмочное тестирование (UAT):
o	участие ключевых пользователей (завхоз, директор, бухгалтер);
o	сценарии из реальной практики (постановка на учёт 100 объектов, инвентаризация кабинета);
o	подписание акта приёмки после устранения замечаний.
•	Критерии приёмки:
o	отсутствие критических ошибок (Severity 1-2);
o	время отклика соответствует разделу 8;
o	успешная выгрузка всех отчётов в требуемых форматах;
o	положительные результаты тестов безопасности (OWASP Top 10).
Дополнительно:
•	Тестовая среда: изолированный контур с копией продуктивных данных (обезличенных).
•	Автотесты: CI/CD пайплайн с запуском тестов при каждом коммите.

o	мастер первичной настройки (пошаговый визард);

o	хранение ПДн только на территории РФ;
o	обезличивание данных при тестировании/аналитике;
o	реестр обработчиков ПДн, политика конфиденциальности.
•	Приказы Минфина и ФСБУ:
o	ФСБУ 6/2020 «Основные средства» (учёт, амортизация, выбытие);
o	Приказ Минфина №52н (инвентаризация, формы актов);
o	соответствие бухгалтерским стандартам бюджетного учёта.
•	Требования муниципалитета:
o	единая нумерация имущества в рамках ОМС;
o	сроки предоставления отчётов (ежеквартально/ежегодно);
o	форматы обмена с централизованной системой (XML-схема).
•	ГОСТы и стандарты:
o	ГОСТ Р 58201-2018 (DataMatrix для маркировки);
o	ГОСТ 7.67-2003 (коды стран и территорий);

Дополнительно:
•	Аудит соответствия: ежегодная проверка на соответствие нормативным требованиям.
•	Юридическая значимость: обеспечение юридической силы электронных документов (63-ФЗ об ЭП).

o	учёт временных выдач, сроки, ответственные, фиксация состояния при возврате.
